# Yams v0.2.0

Yams now follows explicit replacements for outdated knowledge, expands a memory
page's immediate links and backlinks, and gives agents concrete triggers for
consulting project memory. Existing repositories can adopt the updated policy
through a reviewed initialization manifest without rewriting their project page.

## Changes

- `yams-wiki expand WIKI_ROOT SLUG [--json]` returns outgoing links, backlinks,
  unresolved targets, and compact page metadata without loading a model or index.
- `yams-wiki supersede WIKI_ROOT SLUG --by REPLACEMENT` preserves the old page as
  history and records its verified replacement. After indexing, retrieval follows
  replacement chains and returns the current page even with `-k 1`, with explicit
  provenance in text and JSON results.
- Memory policy names when to consult prior knowledge: schemas, public
  interfaces, architecture, dependencies, build/release decisions, recurring
  failures, and recorded decisions. Mechanical edits can skip retrieval.
- `init_manifest: 4` allows policy/schema upgrades and layout migrations to
  preserve an existing valid project page byte for byte when its input is omitted.
  Original policy blocks can be upgraded; customized policies remain protected.

See [graph expansion](https://github.com/MrSeizy/yams/blob/v0.2.0/docs/graph.md)
and [supersession](https://github.com/MrSeizy/yams/blob/v0.2.0/docs/supersession.md)
for the command and compatibility details.

## Upgrade

```sh
brew update
brew upgrade yams
npx skills update
```

Restart an enabled background service with `brew services restart yams`. Run
`yams --index` in each project to backfill replacement metadata. Exact v1/v2
project stores migrate transactionally to v3; compatible v2 embeddings are
reused. Older binaries cannot open a v3 store, but source Markdown remains
portable and can rebuild an index.

The new `graph_expansion: 1` and `supersession: 1` capabilities are additive.
The eight-field frontmatter format, repository layout, and existing search
result fields remain compatible. Shared pages with a noncanonical
`**Superseded by:**` line must repair that declaration before indexing.

Updating the agent skills does not rewrite existing repository policy. Use the
explicit `yams-till` upgrade workflow when adopting the new policy in a project.

## Install

Supported channel: `brew install mrseizy/yams/yams`.
Direct tarball downloads are quarantined by Gatekeeper (binaries are
ad-hoc signed only) and are not a supported install path.

## Known limitations

- The first-run model download (~550 MB) is not yet bounded or resumable;
  interrupt with Ctrl-C and rerun if it stalls.
- Apple Silicon only; macOS floor declared :sonoma, validated on the
  version listed above.
- `yams`, `memory-search`, `yams-service`, and `yams-wiki` all report
  their package version with `--version`.
